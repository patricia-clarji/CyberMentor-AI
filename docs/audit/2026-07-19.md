# CyberMentor AI repository audit — 2026-07-19

## Evidence ledger

- **E1 Setup:** documented `npm install` completed; 257 packages audited, zero vulnerabilities.
- **E2 Automated gates:** `npm run format`, `npm run lint`, `npm run typecheck`, `npm test`, `npm run validate-content`, `npm run evaluate-ai`, `npm run build`, and `npm audit --audit-level=high` completed successfully after fixes. The final orchestrated suite discovered 10 files and passed 94 tests. Dedicated Sentinel evaluation passed 54 tests containing exactly 50 evaluation prompts plus four invariants. Build: JS 249.23 kB (77.80 kB gzip), CSS 24.62 kB (5.92 kB gzip).
- **E3 Live production:** `npm start` served `http://127.0.0.1:8080`; `/healthz` and `/readyz` returned 200. Current live checks verified an empty published catalog/lab/project state, legacy assessment and lab rejection (404), empty verified adaptive pool, one-answer confidence `0.0388`, `credentialEvidence: false`, diagnostic fail-closed, hostile Origin 403, CSP, and structured path-only logs. Earlier live checks also covered malformed JSON 400, oversized body 413, traversal non-disclosure, and rate limiting 429.
- **E4 Source scans:** no client assessment answer/validation fields; no hard-coded credentials; no fake handlers or genuine TODO/FIXME markers; no seeds, workers, uploads, Playwright, or E2E tree. One ten-table adaptive SQL migration now exists. Git reports that the workspace is not a repository.
- **E5 Content/reference review:** 12 records, 48 modules, 144 lessons, eight unique official primary-source targets. NIST, OWASP, MITRE, Python, Linux and NIST AI pages opened; official CISA results validated the CPG and Cloud TRA targets. A distinctive lesson sentence produced no matching web result.
- **E6 Browser limitation:** the required in-app browser backend returned no available browsers after its documented setup/troubleshooting flow. Real-browser console, viewport, and Playwright checks are therefore unverified, not passed.
- **E7 Environment limitation:** Docker is not installed; container build and Compose startup are unverified.
- **E8 Content pipeline:** live retrieval succeeded for seven allowlisted NIST, CISA, MITRE, OWASP, Python, Linux, and RFC Editor sources; final status reports all seven fresh at age zero days. Claim evidence matched the NIST source. Validation completed with zero errors and zero warnings across one non-published fixture, 23 skill nodes, seven sources, and zero publications. Snapshots store only metadata/digests/evidence results, not raw source pages. Publication without independent approvals is covered by a failing gate test.
- **E9 Verified-content boundary:** only current `verified` + `published` version files with exact technical, instructional, accessibility, licensing, and conditional safety approvals can enter learner APIs. Reviewer identities, question keys, lab validation logic, and expected evidence are removed from public payloads. The synchronized manifest contains zero artifacts, and the UI blocks all legacy lessons/labs.
- **E10 Adaptive learning:** transparent mastery, confidence, recency, diagnostic branching, progressive stored hints, verified-pool recommendations, explanations, dismissal, and decision logs are implemented. Eleven adaptive tests cover the six required learner profiles and taxonomy integrity. Instructor policy and durable tenant state remain schema/migration architecture only.
- **E11 Exact quick start:** `npm install` completed (257 packages, zero vulnerabilities). `npm run dev` served Vite at `http://127.0.0.1:5173`, API at `http://127.0.0.1:8787`, and the Vite-proxied published catalog successfully. Production-style `npm start` also remains live at `http://127.0.0.1:8080` after a successful build.
- **E12 Environment boundaries:** Docker and `psql` are unavailable, so Compose and applying `db/migrations/001_adaptive_learning.sql` could not be executed. The migration contains ten tenant-aware adaptive tables and remains unapplied architecture, not a claimed pass.

## Verified journeys and unavailable journeys

Verified through automated DOM integration with a synthetic server publication: catalog search, course opening, existing local enrollment, verified-only lesson navigation, structured blocks, required knowledge check, server grade response, completion persistence, notes/bookmark state, and legacy sequencing exclusion. Live checks verified development and production startup, health/readiness, Vite API proxying, empty-safe catalog/lab/project/adaptive responses, legacy grading/lab rejection, low-confidence mastery update, no-key Sentinel behavior, headers, Origin rejection, and structured logs.

Negative publication gates and pure rollback activation are verified, but a successful author/reviewer/publisher journey was not fabricated because the registry contains no accountable people and the manifest contains no learner artifacts. Not executable because the capabilities do not exist: registration/login/email verification/reset, authenticated instructor policy, administrator CMS, organization isolation, billing/entitlements, uploads, submissions, rubric grading, scenario runtime, workers, isolated labs, and live LLM/RAG. No demo accounts exist.

## Release decision

**Do not release as a production e-learning startup.** The architecture/demo shell is runnable and the content/adaptive boundaries fail closed, but the core learning product is deliberately empty until real humans publish it. Authentication/tenancy/durable storage, the independently authored 12-course curriculum, real assessments/projects/labs, role tooling, real-browser E2E/accessibility coverage, applied migrations, and production lab isolation are blocking requirements.
