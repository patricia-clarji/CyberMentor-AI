# Authoring artifact contracts

All files in `content/drafts/` share the metadata, provenance, claim, evidence, version, and review fields in `content/schema/draft.schema.json`. The executable validator in `scripts/content-pipeline.mjs` applies the additional type contracts below. Placeholder templates are never imported or published.

| Artifact              | Required body fields                                                                                                                                         | Learner delivery boundary                                                              |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| Course                | `title`, `summary`, `learningOutcomes`, ordered `moduleIds`, `completionRuleId`                                                                              | Published catalog metadata only                                                        |
| Module                | `title`, `courseId`, `learningObjectives`, ordered `lessonIds`                                                                                               | Published course structure only                                                        |
| Lesson                | duration, objectives, five or more structured `blocks`, terms, worked example, check reference                                                               | Full reviewed blocks; never a grading key                                              |
| Question              | prompt, at least three options, `correctOption`, objective, skills, explanation, distractor explanations                                                     | Prompt/options only through diagnostic; key stays server-side                          |
| Lab                   | objectives, authorized target, scope, classification, environment, tasks, expected evidence, bounded validation, progressive hints, cleanup, defense, skills | Validation logic and expected evidence stay server-side                                |
| Scenario              | objectives, briefing, decision points, expected evidence, verification logic, hints, debrief                                                                 | Future learner-safe adapter required before delivery                                   |
| Project               | scenario, requirements, deliverables, milestones, rubric, expected evidence, constraints, mentor boundaries                                                  | Reviewed brief/rubric only; private evaluator material needs a separate server adapter |
| Rubric                | criteria, performance levels, passing rule                                                                                                                   | Published criteria; hidden evaluator examples must remain server-side                  |
| Glossary entry        | term, definition, related skills                                                                                                                             | Published text                                                                         |
| Certification mapping | certification, exam version, objectives, skill mappings                                                                                                      | Published mapping with version/date caveat                                             |
| Completion rule       | title, requirements, evidence types                                                                                                                          | Server-enforced rule in production; architecture-only now                              |
| Explanation variant   | skill, misconception, explanation, worked example                                                                                                            | Adaptive engine may select only a published variant                                    |
| Practice activity     | title, skills, prerequisites, difficulty, duration, type, stored hints, verification, explanation                                                            | Adaptive engine may select only a published activity; keys remain server-side          |

Structured lesson blocks support headings, paragraphs, objective lists, definitions, callouts, warnings, reviewed local diagrams/images with alt text, comparison tables, code, terminal output, packet breakdowns, log samples, forensic artifacts, worked examples, misconceptions, knowledge checks, interactive decisions, practice/lab launches, project milestones, references, and summaries.

Dual-use artifacts must declare authorized-local-only scope, defensive counterpart, cleanup, and an independent safety reviewer. External media is rejected; reviewed media must be stored below `/assets/` with alternative text. Every factual claim must map to one or more blocks and to a current allowlisted source snapshot.
